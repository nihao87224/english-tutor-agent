# Vibe Coding Workflow

## 1. 需求阶段

```text
提出想法
→ 识别用户问题
→ 明确范围和非目标
→ 形成 PRD
→ 决策确认
→ PRD 基线冻结
```

## 2. 设计阶段

```text
概要设计
→ 详细设计
→ API/Schema 契约
→ ADR
→ 风险评审
→ 设计基线
```

## 3. 编码任务循环

```text
选择一个任务
→ 只读分析
→ 输出实施计划
→ 人工确认
→ 小步实现
→ 自动测试
→ 独立 Review
→ 修复
→ 人工运行验收
→ Git 提交
```

## 4. 里程碑循环

```text
完成全部任务
→ 契约校验
→ clean DB 验证
→ Android/API E2E
→ 性能与隐私检查
→ 用户验收
→ 里程碑标签
```

## 5. AI 编码约束

禁止：

- “根据所有文档一次性实现整个 App”；
- 未读现有代码就覆盖文件；
- 一次生成大量未来模块空壳；
- 不执行测试就声称完成；
- 用聊天上下文代替 Git、任务卡和 ADR；
- 让同一个 Agent 只写不审。

推荐：

- 任务 0.5–2 天；
- 计划和实现分离；
- 实现和 Review 使用不同会话；
- 每个任务一个或少量清晰提交；
- 优先用本地 stub 或 mocked transport 跑通确定性闭环；
- 真实 Provider 接入后使用回归样本控制质量。
